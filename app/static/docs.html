首页 设置 说明

并行处理

并行分两层，可在设置页调整（即时生效，持久化到 dirs.settings_file，默认 /data/settings.json）：

  • concurrency（并行任务数，默认 1）：同时转码几个文件。增大后多个任务同时进行，会显著提高 CPU/内存占用。
  • av1an_workers（任务内切片并行，默认 0）：每个任务内部 av1an 用多少线程并行编码切片；0 = 自动（av1an 按 CPU 核数分配）。

各取值对资源占用的影响：concurrency × av1an_workers 约等于峰值同时运行的编码进程数。减小编号即时生效：已排队的任务不受影响，当前任务完成后对应的 worker 会自动退出。

工作流程

默认不会自动入队任何文件（watcher.enabled: false）：只有通过首页表单 / API POST /api/jobs 手动指定的文件或目录才会被转码。如需恢复自动监视，在 config.yaml 中设置 watcher.enabled: true。

提交的文件会分析（Dolby Vision P5/P7/P8 → HDR10（保留/附带 RPU），HDR10/HLG/SDR 直接编码），随后按预设的码率/质量参数编码输出为 AV1（SVT-AV1）。

  • 已是 AV1 的源默认跳过（skip_existing_av1）。
  • 成功后源文件默认保留在原位置。可选：在设置页开启「删除源文件」（需要二次确认，危险操作）。

输出行为

默认（dirs.output/dirs.rpu 为 null）转码输出到源文件所在目录下的 av1/ 子目录：

movies/
├── Big Buck Bunny.mkv        # 源文件
└── av1/
    ├── Big Buck Bunny.av1.mkv    # 转码输出
    └── rpu/
        └── Big Buck Bunny.rpu.bin   # 抽取的 Dolby Vision RPU（仅 DV 源且 save_rpu=true）

若在 config.yaml 中配置了固定的 dirs.output/dirs.rpu，则所有输出集中到这些目录。监视器（watcher）会排除 av1/work/rpu 目录，避免把转码输出再次入队。

预设与编码参数

预设可在设置页添加/编辑/删除并持久化（存于 dirs.presets_file，默认 /data/presets.json）。自定义预设可覆盖内置同名预设，内置预设删除后自动恢复 config.yaml 中的定义。

自定义参数（临时覆盖，不落盘）

首页表单的“自定义参数”框，或 CLI --custom key=value（可重复），按 key=value 逗号/分号分隔。值会覆盖所选预设的同名字段：

crf=24,preset=3,target_quality=75-85,film_grain_denoise=true

数字字段自动转 int（crf/preset/film_grain/passes/keyint/extra_split_sec/min_scene_len/tune），布尔字段接受 true/false/1/0（film_grain_denoise），其余按字符串（target_quality、additional_video_params、pixel_format）。预设选 custom 时以默认视频参数为基准，全部由自定义参数决定。

Shot-based 优化器引擎（engine=optimizer）

Netflix 风格的逐镜头（shot-based）编码。av1an 的 --target-quality 是串行探测：先完整探测完一个 chunk 再探测下一个。optimizer 引擎改为所有镜头并行探测，并用插值获得比 av1an 4 次二分更精细的每镜头 CRF：

  1. 分镜：默认用 ffmpeg 的 scdet 滤镜单趟扫描源，不落任何中间文件（scenedetect_engine: scdet）。实测对三个 4K 源，切点与旧的 PySceneDetect 路径一处完全一致、另两处各多一个；整个阶段从 44.7s / 255s CPU 降到 12.2s / 8s。scenedetect_engine: pyscenedetect 可切回旧路径（写一份降采样副本再用 OpenCV 逐帧读）。
  2. 并行探测：用 probe_workers 个 worker 同时探测每个镜头的一串 CRF（probe_crfs），每个探测点按源分辨率、源位深、与正式编码相同的编码参数（仅 preset 更快）编码，再算 VMAF/SSIMULACRA2。送进 libvmaf 前两路统一缩到 vmaf_width（默认 1920，只缩不放、保持比例），因为 vmaf_v0.6.1 是按 1080p 训练的。镜头过长时按 probe_max_frames 取中间一段连续帧。
  3. 选 CRF：对每个镜头在 (CRF, 分数) 曲线上插值，取命中 target_quality 下限的 CRF（区间超出探测范围时钳制到边界）。
  4. 并行编码：所有镜头按各自 CRF 并行正式编码，最后拼接并重新复用源音频/字幕。

启用方式：预设（设置页或 CLI --custom engine=optimizer）里设 engine=optimizer，并配合 target_quality（必填，如 75 或 75-85）。自定义参数同样适用：--custom engine=optimizer --custom target_quality=80 --custom target_metric=ssimulacra2。

配置默认说明
probe_crfs[20,26,32,38,44]每个镜头采样的 CRF 网格；越密越准、探测越多。探测按源分辨率跑，每多一个点就多一遍全片探测。
probe_preset10探测编码的 SVT-AV1 速度档。注意 SVT-AV1 在 4K 及以上（RA 模式）最高只到 M9，填 10+ 实际按 9 跑。比正式 preset 快必然低估成品质量，用 probe_crf_offset 补。
probe_scale空探测分辨率；空 = 源分辨率（推荐）。填了就是在另一个分辨率上测 RD 曲线：4K HDR 实测 960x540 会把 CRF 20..44 压成 5 个 VMAF 点、整条曲线封顶在 91 以下，于是任何 >91 的目标都会让每个镜头掉到网格最低 CRF，成品反而比源更大。核心
probing_rate1探测每隔 n 帧取一帧。>1 会拉大相邻帧间距、让帧间预测变难，从而低估质量；控制探测开销请优先用 probe_max_frames。
probe_max_frames120每镜头探测帧数上限。探测按源分辨率编码，数分钟的长镜头会让每个 CRF 都花上几分钟的 4K 编码；超过上限时取镜头中间一段连续帧（不抽帧，抽帧会歪曲结果）。核心
probe_workers0跨镜头的并行探测数。探测已改为按源分辨率编码，单实例 4K 实测峰值 3.5GB，所以按内存限而不是按核数：0 = 自动（总内存/8）。核心
encode_workers0并行正式编码实例数。每个 4K 实例持有独立帧池（实测 preset6/lp6 约 8GB，与线程数无关），所以实例数必须按内存限：0 = 自动（总内存/8，总编码内存压在半数以下）。核心
encode_threads0每个编码实例分配的 CPU 核数，用 taskset 绑定互不重叠的核心区间，防止多实例线程超订互抢。SVT-AV1 在 4K 下会自发 80+ 线程且无视 -threads，此值不降低单实例内存，只控制并发。0 = 自动（核数/实例数）。
scenedetect_threshold27.0ContentDetector 灵敏度；越高分镜越少、片段越长。
min_scene_len24最小镜头长度（帧），更短的会合并。
max_shots3000镜头数量上限；超过时合并最短的相邻镜头。
max_crf_delta4.0相邻镜头 CRF 差上限（0=关闭）。每个镜头独立命中目标可能导致相邻镜头 CRF 跳变（如 22→31）造成观感不连续；平滑后限制差值。代价是部分镜头可能略低于目标。
min_crf0CRF 硬下限（0 = 用 probe_crfs 最小值）。目标质量不可达时每个镜头都会回落到网格最低 CRF——这正是文件反而变大的机制；设一个下限可以兜底。核心
probe_crf_offset0.0加在插值出的 CRF 上。探测用的 preset 比正式编码快，会低估成品质量；正值把这部分偏差换回体积。
vmaf_width1920送进 libvmaf 前把两路都缩到的宽度（只缩不放、保持比例，非 16:9 源不会被压扁）。vmaf_v0.6.1 按 1080p、3H 视距训练，直接拿 4K 或 540p 去测都在模型适用范围之外。0 = 按原分辨率比。核心
vmaf_model_4kvmaf_4k_v0.6.1.json源宽 ≥ vmaf_4k_min_width 时改用它，并按原生分辨率打分（不再缩到 vmaf_width）。0.6.1 是 1080p/3H 训练的、4k 模型是 4K/1.5H；实测缩到 1080p 打分偏乐观（CRF32 +0.80、CRF38 +1.63），代价是成品变糊。核心
vmaf_4k_min_width2560低于此宽度仍用 1080p 模型 + 降采样。
ssimulacra2_frame_step4仅 target_metric=ssimulacra2：打分侧每 n 帧取 1。SSIMULACRA2 是逐帧静态图像度量，抽帧在统计上成立——这和 probing_rate 完全不同，后者抽的是编码输入、会歪曲 RD 曲线。4K 实测 2.51fps（libvmaf 约 23fps），不抽帧一集要多花 8.3 小时，每 4 帧取 1 约 2.1 小时。
vszip_plugin / bestsource_plugin/usr/local/lib/vapoursynth/…支撑 SSIMULACRA2 的 VapourSynth 插件路径（镜像内已预置）。
vmaf_threads0VMAF 计算线程数；0 = 自动（核数/probe_workers）。ffmpeg libvmaf 自身默认单线程，4K 下实测 7.0s vs 8 线程 2.1s（分数一致）。
vmaf_model/usr/share/model/vmaf_v0.6.1.jsonVMAF 模型。也接受 version=…。
ssimulacra2_modelversion=ssimulacra2SSIMULACRA2 模型。注意：官方 libvmaf 2.3.1 不含 ssimulacra2，需自备兼容模型（path=/x/ssimulacra2.json）或带 ssimulacra2 的 libvmaf。
fractional_crffalse把小数 CRF 传给 SVT-AV1（更精细；需编码器支持）。
keep_probesfalse保留探测临时文件（调试用）。

资源占用：探测/编码阶段会并行启动 probe_workers 个 SVT-AV1 实例；为防线程爆炸，每个实例的 SVT 线程数（lp）会自动按 核心数 / workers 分配，总线程≈核心数。若机器内存紧张请降低 probe_workers。临时文件在 dirs.work（成功/失败后清理，除非 keep_temp/keep_probes）。

预设置的 probing_rate、probe_res、probe_video_params（如 preset=10 或 copy）、vmaf_threads、probing_vmaf_features（原样透传给 libvmaf 的 feature=）会覆盖上面的全局默认值。

Dolby Vision / HDR

来源处理
P5（ICtCp）libplacebo（Vulkan）转 HDR10 BT.2020+PQ。它是 ffmpeg 里唯一能应用 RPU 的滤镜，没有备用方案（旧的 zscale 已退役）。
P7 / P8剥离 RPU/EL 后编码基底层；RPU 单独保存为 .rpu.bin。
HDR10 / HLG保留 mastering display / CLL 元数据（hdr.preserve）原样编码。
SDRBT.709 直接编码。

环境变量覆盖

任何配置均可通过环境变量覆盖（容器内优先于 config.yaml）：AV1TC_<段>_<键>，例如：

AV1TC_TRANSCODE_VIDEO_CRF=26
AV1TC_WEB_PORT=9090
AV1TC_WATCHER_MIN_SIZE_MB=5

布尔值接受 1/true/yes/on，数字自动转换。

CLI 用法

python3 -m app.cli run                    # 完整运行（监视+队列+Web）
python3 -m app.cli process <file> --single --custom crf=24 --custom preset=3
python3 -m app.cli process <file> -p compact
python3 -m app.cli scan                    # 把输入目录现有文件全部入队
python3 -m app.cli presets                 # 查看当前预设
python3 -m app.cli status / cancel / check
